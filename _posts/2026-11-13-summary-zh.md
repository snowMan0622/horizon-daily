### [Rust 1.100 发布：稳定 never 类型与自定义分配器](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 8.0/10

Rust 1.100 已发布，稳定了 never 类型和自定义分配器，并带来多项 Cargo 改进。Cargo 新增“依赖冷却”配置（RFC 3923）：设置后解析器会忽略发布时间晚于该阈值的版本，除非这些版本已存在于 Cargo.lock 中。Cargo 还会默认以警告形式报告未使用的依赖，\`cargo install\` 默认使用 .crate 包内已有的锁文件，使 \`--locked\` 变为空操作。社区评论还指出，\`bool::toggle\(\)\`、\`Box::map\(\)\`、\`str::trim\_prefix\(\)\` 等稳定 API 未在博客正文中提及。

hackernews · mbStavola · 11月12日 18:39 · [社区讨论](https://news.ycombinator.com/item?id=50472038)

**「背景」** Rust 1.100 是 Rust 工具链的一次常规版本发布，延续了每六周发布一个稳定版的节奏。此前 Cargo 的依赖解析只按版本约束选择最新可用版本，而本次引入的依赖冷却（RFC 3923）允许通过配置让解析器忽略发布时间过短的新版本，除非该版本已记录在 Cargo.lock 中。

**「对用户的影响」** 启用依赖冷却的项目在解析新依赖时会跳过过新的版本，从而降低引入刚发布版本的风险，但已锁定在 Cargo.lock 中的版本不受影响。未使用依赖警告默认开启，可能让现有项目在构建时出现新的警告，需要清理或调整 lint 配置。

**「社区讨论」** 有评论者对 never 类型、自定义分配器和依赖冷却表示欢迎，并特别称赞未使用依赖警告。另有人指出本次稳定内容之多，以至于博客未列出 \`bool::toggle\(\)\`、\`Box::map\(\)\` 等 API；也有用户抱怨编译速度慢、需要频繁清理大量临时文件。

### [UMAP 0.6 发布：新初始化与优化器提速](https://www.reddit.com/r/MachineLearning/comments/1xudaah/umap_06_new_initialization_new_optimizers_and/) ⭐️ 8.0/10

UMAP 0.6 已发布，可通过 \`pip install -U umap-learn\` 或 conda-forge 安装。维护者称，借助对 PyNNDescent 的更充分利用，近邻搜索约快 4 倍；新的递归初始化用 UMAP 自身先铺出粗粒度图结构再逐层细化，使优化器在更少轮次内收敛到最终布局 3% 以内。新优化器引入高效的硬负样本挖掘并放宽了对排斥强度的限制，在百万级数据上能解析更细的簇结构；固定种子下可多线程复现，而 0.5 的种子运行是单线程、耗时 52 分钟，作者称 0.6 在 300 万篇 arXiv 论文上不到 5 分钟完成。新初始化与优化器目前需设置 \`compatibility\_layout=False\` 才启用，因为会改变输出，未来版本将设为默认；上述性能与质量数据均为作者自报，尚未经独立验证。

reddit · r/MachineLearning · /u/lmcinnes · 11月12日 13:51

**「背景」** UMAP 是广泛使用的降维与可视化库，此前版本（如 0.5）在大规模数据上受限于近邻搜索速度、初始化质量以及优化器对吸引-排斥谱范围的限制。0.6 版将新的初始化与优化器设为需显式开启（设置 compatibility\_layout=False），因为二者会改变输出结果，维护者表示未来版本才会将其设为默认。

**「使用影响」** 现有用户升级后默认行为不变，但若想获得新初始化与优化器带来的速度和细节，需要显式设置 \`compatibility\_layout=False\`，并预期嵌入结果与 0.5 不同；依赖固定布局的下游流程应先对比输出再切换。

**标签**: `#umap`, `#dimensionality-reduction`, `#machine-learning`, `#open-source`, `#performance`
